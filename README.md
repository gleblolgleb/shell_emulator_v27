# OS Shell Emulator

## 1. Общее описание
Эмулятор языка оболочки ОС, имитирующий работу в командной 
строке UNIX-подобной ОС. Работа ведется с виртуальной 
файловой системой (VFS).
Вариант №27.

## 2. Описание функций и настроек

### Этап 1: REPL
- **VFS** — виртуальная файловая система с настраиваемым
  именем (по умолчанию `my_vfs`).
- **Parser** — парсер команд с раскрытием переменных
  окружения реальной ОС:
  - Поддерживает `$VAR` и `${VAR}` (например, `$HOME`).
  - Корректно обрабатывает аргументы в кавычках.
- **Commands** — команды-заглушки:
  - `ls [args]` — выводит имя команды и аргументы.
  - `cd [args]` — выводит имя команды и аргументы.
  - `exit` — завершает работу эмулятора.
- **REPL** — цикл чтения-вывода с приглашением вида
  `my_vfs$ `.
- **Обработка ошибок** — выводит сообщение об ошибке
  при вводе неизвестной команды.
### Этап 2: Конфигурация
- **Параметры командной строки:**
  - `-v, --vfs-path PATH` — путь к физическому расположению VFS
  - `-s, --script PATH` — путь к стартовому скрипту
- **Отладочный вывод** — при запуске отображаются все заданные параметры
- **Стартовый скрипт:**
  - Выполняет команды последовательно
  - Ошибочные строки пропускаются (не прерывают выполнение)
  - Поддерживает комментарии (строки, начинающиеся с `#`)
  - На экране отображается и ввод (`> команда`), и вывод
- **Тестовые скрипты** находятся в папке `scripts/`:
  - `test_default.bat/sh` — запуск без параметров
  - `test_with_script.bat/sh` — запуск со стартовым скриптом
  - `test_with_vfs.bat/sh` — запуск с путём к VFS
  - `test_all.bat/sh` — запуск со всеми параметрами
## Этап 3: VFS
- **VFS Storage** — виртуальная файловая система в
  памяти:
  - Загрузка из ZIP-архива (параметр `-v путь`).
  - Все операции производятся в памяти, без распаковки
    на диск.
  - Двоичные данные кодируются в base64 при сохранении.
- **Команда `vfs-save путь`** — сохраняет состояние VFS
  на диск в ZIP-архив.
- **Обработка ошибок загрузки VFS:**
  - Файл не найден: `Error: VFS file not found: путь`.
  - Неверный формат: `Error: Invalid VFS format: путь`.
- **Тестовые VFS** генерируются скриптом:
  ```
  python scripts/generate_test_vfs.py
  ```
```
vfs_test/minimal.zip
```
минимальный (1 файл).
```

```
несколько файлов.
```

```

## Этап 4: Основные команды
- Команда **ls** с поддержкой флагов:
  - Без флагов — список файлов и папок
  - a — показать скрытые файлы (начинающиеся с .)
  - l — длинный формат (размер, дата, имя)
  - h — человекочитаемый размер (K, M, G)
  - Комбинации флагов: -la, -lh, -alh и т.д.
- Команда **cd** — смена текущей директории:
  - Поддерживает абсолютные и относительные пути
  - Поддерживает .. для перехода на уровень выше
- Команда uptime — показывает время работы эмулятора в секундах
- Команда echo — выводит аргументы (с раскрытием переменных окружения)
## 3. Команды для сборки проекта и запуска тестов
### Запуск эмулятора
```
make run
```
или
```
python -m src.main.py
```
### Запуск тестов
```
make tests
```
или
```
pytests -m pytest tests/
```
## 4. Примеры использования
Без параметров (интерактивный режим):
```
python -m src.main
```
Со стартовым скриптом:
```
python -m src.main -s scripts/startup_example.sh
```
С указанием пути к VFS:
```
python -m src.main -v /path/to/vfs
```
Со всеми параметрами:
```
python -m src.main -v /path/to/vfs -s scripts/startup_example.sh
```
Пример вывода стартового скрипта:
```
=== Debug: Configuration ===
VFS path: (not set)
Script path: scripts/startup_example.sh
============================
> ls -la /tmp
ls: -la /tmp
> cd /home/user
cd: /home/user
> unknown_command_should_be_skipped
Unknown command: unknown_command_should_be_skipped
> exit
```
